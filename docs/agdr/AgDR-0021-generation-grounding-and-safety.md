# AgDR-0021 — Generation, grounding, and safety boundaries

> In the context of deleting prose comments from `src/server/generation`, `src/server/grounding`, `src/server/moderation`, `src/server/limits`, `src/server/safety`, and `src/server/curriculum` (AgDR-0019), facing the loss of recorded gate, retry, scrub, and pack contracts that no single type restates, I decided to consolidate the harvested decisions here, to keep every boundary fail-closed and every bound owned by one module, and to accept that the record is prose read at review time.

Recorded 2026-11-21. Harvested from code comments deleted by the comment-free-source sweep ([AgDR-0019](AgDR-0019-comment-free-source.md)).

## Artifact gate and recovery ([#28](https://github.com/abodacs/edu-canvas/issues/28), `src/server/safety`, `src/server/a2ui`)

- A renderable artifact is a branded type minted only by `gateArtifact`; the module-private symbol makes an outside literal a type error, and a runtime guard stops a JavaScript caller from compiling a raw draft. Type signatures keep callers honest at compile time; the brand proves it at runtime.
- The compile guard is fail-closed: any pre-render rejection is a hard block. Unknown component, action, catalog, or payload is replaced; every schema, identifier, relationship, or math break is edited; bounded infrastructure failure is retried. The one code-to-recovery table lives in `recovery-policy.ts`; a lesson-level refusal takes the strongest actionable recovery among its findings (retry, then replace, then edit); a warning never blocks and always asks for an edit.
- Preview and Share re-derive the gate from the stored artifact and prove the acceptance snapshot still describes it — the stored verdict alone is never trusted. The gate hash covers the artifact's variants and validated learning path; wrapper metadata (request, provenance, timestamps) stays outside it. The compile guard only sees the rendered projection, so a draft or semantic rule it cannot observe is stricter by design; every such case names the reason in the corpus table instead of weakening the gate to make the seams agree.
- The compile seam owns one error contract: the preview server feeds every `LessonPreviewCompileError` back into the gate as a pre-render refusal, so a story that cannot be built reaches the teacher as a named refusal, not an unhandled failure. The raw compiler and raw fraction compiler are the test and differential-oracle seams only; production must call the branded `compileLessonPreview` / `compileFractionPreview`.
- The differential oracle lives under `src/server/a2ui` because the drafting context may not import preview compilation; the reverse direction is allowed for test modules by the architecture harness. The corpus module stays in `src/server/generation` for the same reason; the oracle test assembles both contexts.
- A hard-blocked artifact has no renderable artifact and no snapshot; the compile seam is never called. Gate findings become record diagnostics on a hard block, each keeping its recovery action; a prior diagnostic with the same identity contributes its recommendation.

## Semantic validation and the advisory reviewer ([#223](https://github.com/abodacs/edu-canvas/issues/223))

- The inline semantic runner is clamped to 5000 ms and turns a timeout into `hard_block` `VALIDATION_TIMEOUT`. The advisory reviewer therefore runs after `ready-for-review`, never inside `validateSemanticLesson`: inside the clamp every slow-but-fine draft would read `failed-retryable`. The reviewer owns a longer bound (the whole generation budget), one attempt only — a retry would double the teacher's wait for an advisory result.
- The advisory result is warning-only by construction: the stored shape has no verdict field, so a reviewer result cannot express a block; the response parser clamps a disobeying model's verdict to a warning. It appends to a separate additive field; it never changes the draft, state, diagnostics, gate snapshot, or an answer key; a failed review is never written.
- The reviewer never sees private answer pairs: the advisory input clone drops relationships and everything else the reviewer does not need. One shared text boundary sanitizes model-authored recommendation fields for both the inline runner and the reviewer, so an echoed answer key, credential marker, or student wording cannot reach a teacher-facing finding.
- The provider response schema is strict, so optional fields are required-and-nullable rather than absent. An unavailable provider is a 503, not a draft failure — the reviewer is optional.
- The eval-cases module is test-support evidence, not a production entry point; it lives outside production modules so generation no longer imports seed data.

## Provider, prompts, and limits ([#104](https://github.com/abodacs/edu-canvas/issues/104), `src/server/generation/service.ts`, `src/server/limits`)

- The provider prompt is framed by the standards pack ([#221](https://github.com/abodacs/edu-canvas/issues/221)): the task line, both group labels, the item counts, the curator reference, and the answer rule's declared problems or passage all come from the pack. Answers are never included — the rule owns them. The deterministic fixture builds its draft from the same values, so an offline run obeys the pack's own answer rule and describes the same task as a live call.
- Reaching the provider without a limit decision is exactly the bypass the limits port closes, so the state is a required dependency of the service. The service's provider call site is the single choke point: every provider call, including a correction, reserves shared limit state first; a correction counts against the provider-call budget but not the attempt or authoring budgets. An unavailable limit store fails closed with a bounded wait.
- A limited verdict consumes nothing: one conditional write checks and increments in the same transaction, and a rejection rolls back every increment already applied. The 429's retry interval is the window's real remaining time, never sooner than the minimum hint (a sub-second hint invites a hot retry loop). The lease is reclaimable after its duration; it is never a permanent lock; the holder names the attempt so a worker that lost its claim cannot release someone else's lease.
- Idempotency keys are persisted and looked up across deploys, so the digest stays FNV-1a; changing it would orphan every in-flight retry across a deployment.
- Retries are sequential by design: each attempt settles before the next starts and the previous attempt is aborted first. Polling is sequential for the same reason. A provider error, timeout, limit rejection, or cancellation must release the claim lease instead of leaving the teacher locked out until expiry.
- The delivery seam parses the body with `lessonGenerationInputSchema`; the service owns only what the schema cannot say: which grades and standards the product supports for the acting tenant, and the derived idempotency key. Without a tenant there is no private-pack resolution: only a shared template may answer, so another tenant's pack never makes a standard "supported" for everyone.
- A revision ([#148](https://github.com/abodacs/edu-canvas/issues/148)) is a new request that names the blocked one: the link is written with the new request, never with the blocked row (which stays byte-for-byte unchanged), and the link stays out of the request hash so the moderated-hash guard remains the same-prompt refusal. A retry that does not name a source inherits the original request's reviewed source so metadata and hash stay comparable.
- The draft carries the enriched provenance acceptance wrote (pack version, allowed screen patterns); the record and attempt must expose the same provenance or preview falls back to matching-only. Source resolution completes before the claim so the remaining lease is reserved for generation, validation, and persistence.
- The deterministic provider accepts credentials committed to this repository but must never authenticate a deployed request, so that gate lives in config, not beside the factory.

## Source grounding ([#114](https://github.com/abodacs/edu-canvas/issues/114))

- Source snapshots are immutable: repair creates a new row linked through `replacesSnapshotId`. A snapshot is only complete when the requested standard resolves to a real standards pack (the registry is resolved directly so an unknown standard cannot report a false positive), the teacher has reviewed it, and it has not expired. The source gate throws before the generation claim, so a blocked source never burns an attempt.
- Extraction runs in a `worker_threads` worker capped at 128 MiB with a 10 s abort deadline (the measured unpdf prototype stays inside both); the worker is created from an eval script importing unpdf by module URL so the server bundle keeps one statically imported copy while the parse stays off the main thread; no temporary files exist at any point. Cancelling terminates the worker and is safe to call twice.
- Encrypted PDFs carry `/Encrypt` in the trailer; scanning the tail keeps the pre-parse rejection cheap and avoids matching the literal inside content streams. A page whose extracted text is mostly non-letters is suspected broken math (fraction bars and glyphs survive extraction as isolated symbols); the heuristic is conservative on purpose and the gap message says "suspected".
- An `extracting` snapshot left behind by a crashed process is marked failed after the extraction ceiling; live extractions finish in at most 10 seconds. The cleanup sweep starts lazily with the delivery module's first request, runs as the table owner (RLS is ENABLE, not FORCE) with no tenant context until [#100](https://github.com/abodacs/edu-canvas/issues/100) lands the least-privilege role split.
- Public diagnostics scrub teacher-facing copy and replace it when it carries an answer key, a secret, a token, raw provider text, or a student identifier; the teacher still sees that a check fired and what to do. Every finding carries exactly one recovery action ([#28](https://github.com/abodacs/edu-canvas/issues/28)) and the moderation category behind a block never carries the rule set, matched text, or internal code ([#132](https://github.com/abodacs/edu-canvas/issues/132)).
- List projections of source snapshots never carry extracted text; the single-snapshot review view does, because it is the teacher's own material.

## Standards packs and the Learning Commons adapter ([#217](https://github.com/abodacs/edu-canvas/issues/217), [#218](https://github.com/abodacs/edu-canvas/issues/218), [#222](https://github.com/abodacs/edu-canvas/issues/222))

- A pack is versioned data, not a code branch; the schema is strict, so an unknown field is a mistake rather than an extension point, and a pack version must differ from the graph version it embeds: editing the graph produces a new pack, never a silent in-place change. Acceptance blocks with `PREREQUISITE_PACK_MISSING` when no pack resolves — the context is never synthesized from another standard's graph.
- The frame chooses the matching draft's item counts, so both stay inside the structural validator's caps (3–8 source items, at most 8 targets): a pack asking for anything else could never produce an acceptable draft. Pack examples keep the offline draft on the pack's own answer rule for every subject.
- The Learning Commons adapter owns one transport seam: every method maps to a fixed REST path; a provider field can never select a URL. The API key stays in the header and is never logged; redirects are errors so the key cannot follow a provider redirect to another host. Every provider loop has a page ceiling — a provider that keeps saying `hasMore: true` can spend the total deadline but cannot keep the adapter in an unbounded loop, and a cap never becomes a claim of absence.
- Provider responses stay `unknown` until the adapter parses them. A provider failure keeps only the HTTP status, never the raw body (a payload can carry standard text, a token echo, or unrelated tenant data). A 4xx says the path or credential is wrong — it stays distinguishable from a genuine empty 200. The pipeline was verified live on 2026-11-04; the matrix and per-row facts are in `docs/research/standards-generalization/live-matrix.json`.
- The pilot registry is versioned data ([#218](https://github.com/abodacs/edu-canvas/issues/218)): adding a supported `{jurisdiction, statementCode}` row is an entry, never a branch. A lookup never guesses: an outside envelope is `unsupported-envelope`; a supported envelope with no row is `standard-absent`. A state standard with no direct prerequisite uses its best CCSS crosswalk, and the resolution says so. California is out of scope (product decision 2026-11-04); the adapter keeps its exact-crosswalk path as data. Provider shapes were verified live 2026-11-04: every collection is `data[]` with a `pagination` object; extra provider keys are accepted but never retained; grouping rows (Domain, Grade Level) have a null statement code and are real rows, never malformed envelopes.

## Moderation ([#132](https://github.com/abodacs/edu-canvas/issues/132), `src/server/moderation/content-safety.ts`)

- One local code per boundary: `MODERATION_BLOCKED` means a local rule fired; a provider-side moderation refusal must carry its own code and never reuse this one. The rule-set fingerprint is available to callers that log or measure but is not persisted into the public diagnostic schema — it would leak the rule fingerprint to the client.
- Source material (uploaded extraction or corrected text) is untrusted data, never authority; screening also catches personal data so a blocked source never persists text and never reaches preview (UC5).
- Instruction-override rules stay narrow on purpose: a Grade 4 prompt may say "ignore the extra practice", so the rule needs an instruction target, not a bare verb; each pattern allows zero, one, or two qualifiers between the verb and the target.
- The blocklist holds unambiguous harm phrases, not single words, so a fractions lesson cannot match it; adding an entry requires a category test and a rule-set version change. Slur coverage is deliberately absent — it belongs to a provider moderation layer, not a committed word list.
- The email-local-part scan is bounded by RFC 5321 lengths: an unbounded local part re-scans from every word boundary and cost 884 ms on a 30 kB source; with the bound it costs under 15 ms. The digit lookahead keeps the identifier rule on values carrying a number ("ask each student number their paper" passes; "student id 4471" blocks).
- First names only: surnames are excluded because many are occupation or common words, and nature/month names for the same reason; the bake-off evidence in `docs/hackathon/meta-global-2026/evidence/moderation-2026-10-31` records what this costs in recall. Structured shapes (emails, phones, ids) are separate from first names — Grade 4 word problems are full of reviewed first names, so a generated lesson must not be blocked for teaching a fraction; names are screened on teacher input and on source text, where a roster is the realistic risk.
- Category order is the reported category: personal data outranks markup, so the teacher sees the revision that matters most.
- The teacher's own prompt stays in their request row so the revise flow can show it ([#119](https://github.com/abodacs/edu-canvas/issues/119)) — deliberate product behaviour recorded by the prompt-exposure canary; retention of a blocked prompt is the open [#101](https://github.com/abodacs/edu-canvas/issues/101) governance question.

## Alternatives considered

- **Keep these contracts as comments** — rejected by [AgDR-0019](AgDR-0019-comment-free-source.md); the gate, retry, scrub, and pack tables are the code-level owners, this record is the review-time index.

## Consequences

- The gate/recovery tables and the limit arithmetic remain the executable truth; where this record and a test disagree, the test wins and this record is stale by definition.
- New boundaries (a second provider, a new moderation layer) should extend this record rather than introduce prose beside the code.
